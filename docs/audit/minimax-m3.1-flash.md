# Audit: honesty of user-facing text — commit 8622869 (feat/ai-booking-research)

**Verdict:** Largely honest — booking "nothing reserved" and missing-key messages match the code — but two strings can mislead (the research brief's "no live web search is set up" caveat, and the unconditional "I will message you on Telegram"), and the README has three small accuracy gaps.

1. **Medium — server/index.mjs (`POST /api/research`, caveat line) with server/assistant.mjs (`researchMeeting`).** The brief's caveat tells the user "No live web search is set up (SEARCH_API_KEY), so this is from general knowledge" whenever `brief.live` is false — but `live` is just `sources.length > 0`. Sources come back empty not only when the key is missing but also when the Brave call *fails* (`await webSearch(...).catch(() => [])`), returns zero results, or the LLM returns no `query` (`target?.query ? await webSearch(...) : []`). So with `SEARCH_API_KEY` correctly set, a single Brave outage makes the glasses state a falsehood about the server's configuration. Also, when the model obeys its prompt with `<sources>none</sources>` ("if a fact is not in the sources, say it is unknown"), the caveat's "this is from general knowledge" mislabels the content. *Smallest fix:* have `researchMeeting` return a reason (`'no-key' | 'no-results' | 'no-query'`) and tailor the caveat: "the search failed/found nothing" instead of "not set up" when the key exists.

2. **Medium — app/src/render.ts (`reminder` case) and app/src/machine.ts (`saved` case).** Both show "I will message you on Telegram." unconditionally. In demo mode (`TELEGRAM_BOT_TOKEN` unset) `sendTelegram` only appends to a demo outbox and logs (server/telegram.mjs), and when Telegram is on but the owner chat is not yet paired, delivery is `pending-pairing` — nothing arrives. The server already computes this (`addReminder` returns `delivery: 'telegram' | 'pending-pairing' | 'demo'`), but `api.saveReminder` types only `{ scheduled: boolean }` and the client drops it. *Smallest fix:* thread `delivery` into the response type and vary the line: "I will message you on Telegram" / "I will remind you here (demo)" / "Reminds you once the bot is paired".

3. **Low — app/src/machine.ts (`bookingSaved` case) vs server/index.mjs (`POST /api/bookings`).** The server returns a kind-specific `note` ("It is not on your calendar yet." for meetings/appointments, "Nothing was reserved: no booking provider is connected." otherwise), but `api.saveBooking` types only `{ id; reserved }` and the machine hardcodes "Nothing was reserved with a provider yet." for every kind — so a meeting booking gets the provider wording while the accurate calendar wording is discarded, and neither mentions that a reminder *was* set (the only thing the code actually does). *Smallest fix:* return and render `note`, or at least add "Saved with a reminder." to the done screen.

4. **Low — server/index.mjs (`POST /api/ask`) vs `POST /api/research`.** Ask answers render on the same `brief` screen as research briefs but carry no sourcing hint: `askCompanion` is model-only, while research gets an explicit general-knowledge/live-search caveat. A user cannot tell a sourced brief from a bare model answer. *Smallest fix:* append a short "From general knowledge, no web search." line to ask answers (the `askCompanion` prompt already says "say when you are not sure").

5. **Low — README.md (env table in "Run it").** The table documents `TELEGRAM_BOT_TOKEN`, `LLM_*`, `STT_*`, `ICS_URL`, `APP_TOKEN` but omits `SEARCH_API_KEY`, which `.env.example` documents and the "Research my next meeting" bullet depends on. *Smallest fix:* add a `SEARCH_API_KEY` row.

6. **Low — README.md ("Tests": "npm test runs 123 tests") and docs/SUBMISSION.md ("114 automated tests").** Both are stale: I ran the suite at this commit and it reports **129 tests, 129 passed** (8 files, all green). *Smallest fix:* update the counts, or write "runs the full test suite" to avoid a number that drifts.

Checked and honest, for the record: the booking confirmation flow ("Book this?" → explicit Save → "Nothing was reserved…" — server test asserts `reserved: false` and a note containing "Nothing was reserved"), the `/api/ask` 501 message naming `LLM_API_KEY`, the research-without-key fallback ("Full research needs an AI key on the server"), default-time labels suffixed "(default)" in `llmIntent`, README's ping-throttle (30 s = `NOTIFY_GAP_MS`), 60-minute Telegram retention (`TTL_MS`), and the "no provider connected yet" commit message.
