# Audit: commit 8622869 — tests and edge cases

**Verdict:** happy paths are well covered, but every LLM/search failure path on the new endpoints is untested and several of them fail in ways the tests would catch; the render-budget test skips all four new screens.

1. **High — server/assistant.mjs:27-38, server/index.mjs:154-162.** `researchMeeting` lets a malformed model reply crash the endpoint. `chatJson` (server/llm.mjs:26) does `JSON.parse(content)` with no try/catch, so a model that returns non-JSON throws; `POST /api/research` calls `researchMeeting(event)` with no guard, and the server maps any non-`HttpError` to "Upstream service failed: …". Same for `chatText` timing out or returning a 5xx. No test exists: `tests/llm.test.ts` closes the fake LLM after one outage case covering only `/api/threads` and `/api/draft`, and never hits `/api/research`. Smallest fix: wrap the `chatJson` call in `try { } catch { target = null }`, wrap the `researchMeeting` call in `/api/research` the way `draftReply` wraps its own, and add an llm test where the fake returns `content: 'not json'` for research.

2. **High — app/src/runtime.ts:56-79, main.ts:72.** `Runtime.checkAlerts` has zero coverage. `startAlerts` is called only from `main.ts`, which no test imports (`runtime.test.ts`, `voice.test.ts` never touch it), so the since-cursor update, dedup by threadId, reminder-first sort, and the 25 s/90 s expiry dispatch are all unexercised. Note also `this.alertSince = Math.max(this.alertSince, a.at)` runs before the machine decides whether to show the alert, so a message alert dropped on a busy screen is never retried. Smallest fix: a runtime test stubbing `/api/alerts` twice (message while busy, then idle), asserting the card appears or is dropped, plus an expiry check.

3. **Medium — tests/machine.test.ts:113-127.** The render budget test still enumerates only `reminder`, `draft`, `meeting`, `error`. The new `brief`, `booking`, `alert` and question `prompt` screens are missing. That matters because `pages()` (app/src/text.ts:23) uses `wrap(text, COLS, Infinity)` — no truncation at all — so a long word over 40 chars or a header like `'Brief: ' + company` reaching `clip(s.title, COLS)` is unchecked. Smallest fix: add those four screens with a 300-char payload to the existing loop.

4. **Medium — server/index.mjs:146-152 vs tests/server.test.ts:201-204.** `/api/ask` when the LLM is up is untested end to end: the demo test only checks the 501-without-key branch, and `llm.test.ts` never posts to `/api/ask`. A regression that drops the `(await askCompanion(q)) || fallback` guard would go unnoticed. Smallest fix: one case in `llm.test.ts` posting `/api/ask` and asserting the served text plus the empty-content fallback string.

5. **Medium — server/index.mjs:139.** `POST /api/bookings` calls `addReminder` for the companion reminder but ignores its outcome, so the two documented failures are silent: a colliding id throws 409 when that reminder id holds a different payload, or 429 at 200 pending reminders (index.mjs:44). Either way the booking row is still appended and returned as saved, without a reminder. The test file covers duplicate booking ids only. Smallest fix: let the error propagate (or check the result and drop the note), and test a booking whose reminder id collides.

6. **Medium — server/assistant.mjs:9-16.** `webSearch` is entirely untested: no fake Brave server anywhere (`grep SEARCH_API_KEY tests/` finds nothing). Nothing verifies its failure modes: a non-2xx throws (swallowed at assistant.mjs:33, so research degrades silently), a bad body rejects in res.json(), and a missing web.results yields an empty list. Smallest fix: add a node http fake returning `{web:{results:[…]}}` and a 500, and assert `sources.length` and `live` both ways.

7. **Low — server/index.mjs:87.** The `book` intent's invalid-date handling is untested. `Date.parse(out.whenISO) > now` sends any past or garbage `whenISO` to `now + 3600000` with `' (default)'` appended to the label; `tests/nlu.test.ts` adds no book/ask/research case and `llm.test.ts` only exercises the reminder shape. Smallest fix: one `llm.test.ts` parse case with a past `whenISO` and `kind: 'flight'`, asserting the defaulted time.

8. **Low — server/index.mjs:193-203.** Snooze keeps the original reminder due, so it re-fires and re-queues on the glasses (the queue entry is deleted but the reminder is not marked delivered); no test asserts a snoozed reminder stops appearing in `/api/alerts`. Smallest fix: mark `r.delivered = true` on the snoozed row and extend the existing snooze test to poll `/api/alerts` once more.

Clean areas: readJson rejects malformed bodies, STT outages map to 502 (voice.test.ts), send idempotency, the booking kind whitelist, and the machine transitions for alerts, paging and booking confirmation.
